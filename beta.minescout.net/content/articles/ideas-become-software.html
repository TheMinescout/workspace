IDEAS BECOME SOFTWARE

NOV 27, 2026 · LAB DIRECTION · CATALOGUE UPDATE

System entry / direction

Minescout Beta is not a staging copy of the main site, and it is not a client-services page. It is the place where independent software projects are built, documented, and published. The short version of that role is the new line on the homepage: ideas become software.

This entry records the change in how the lab presents its work. The identity did not change. The catalogue finally caught up with it.

ATLS is what Minescout has written. PRDS is what Minescout has built. The release log is what changed, and when.

01 / The role of Beta

Minescout Studio builds for clients. The Chop Lab explores 3D design and AI CAD. Minescout Tools supports the development infrastructure. Beta is the part of the ecosystem that can build something completely different, publish it, and let people use it without having to justify every experiment as a business opportunity.

That means the site needs to do three things well:

EXPLORE

Experiment with ideas. Start with a question, a constraint, or a tool that should exist.

BUILD

Develop original software. Ship small, self-contained tools that run in the browser.

PUBLISH

Document and share it. Release notes, design decisions, and the history behind each build.

02 / What changed in PRDS

The project index used to be a list. It now behaves like a catalogue. Every project carries the information needed to judge its state before opening it:

  • Status — Stable, Experimental, or Archived.
  • Version — the release currently described.
  • Last updated — the date the catalogue was last changed for that project.
  • Launch or download — a direct route to the software.
  • Related ATLS — the release notes or technical entry that explains it.

The status is the important part. A project that has not shipped since November 2025 should say so instead of looking permanently active. An experimental branch should look experimental. An archive should look archived.

Open the project catalogue to see the current set, including the new experimental Crypto Toolkit v2 roadmap.

03 / Development histories

A download page answers “what is this?”. A development history answers “how did it get here?”. Each project now has a detail page with a short record of its phases: concept, prototype, release, and what comes next.

This is deliberately modest. It is not a commit log. It is the engineering story that would otherwise be lost between releases. The Crypto Toolkit entry is a useful example: the frequency chart came before the solver, because the chart is what tells you which attack to run.

04 / ATLS as a publication

ATLS is no longer only a release-notes index. Publications are typed so the archive can grow beyond announcements:

  • Release notes.
  • Technical explanations.
  • Design decisions and retrospectives.
  • Research and development logs.
  • Tutorials.

The existing entries keep their original text. They now carry a type, a reading time, and a link back to the project they describe. The ATLS index can be filtered by type.

05 / The release log

Following a project should have a visible result. The new release log combines project updates and ATLS publications into one chronological feed. Projects can be followed from their detail page or from the catalogue; the follow state is stored in this browser, not on a server.

The homepage uses the same data for a “since your last visit” module. It is a small feature, but it gives the site a reason to be revisited without pretending to be a social platform.

06 / Feedback stays specific

The requests channel already existed. It now accepts a project context: opening a request from a project detail page pre-fills the project name, and the message body records which project the request belongs to. That keeps feedback attached to the software instead of arriving as an anonymous suggestion.

07 / What this is not

This is not a community platform. There are no public profiles, no voting mechanics, and no attempt to manufacture engagement. It is also not a redesign for its own sake: the charcoal surfaces, warm orange accent, monospace type, and ATLS/PRDS structure are the same visual system the site already used.

The next milestone is not another identity. It is making the catalogue, the histories, and the publications genuinely useful.
